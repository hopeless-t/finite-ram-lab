# OBS-001 — Dual-Sided Memory Observation Baseline

> **Status:** IMPLEMENTED / INITIAL CONTRACT

## Question

Can application-side demand transitions and OS-side memory behavior be placed on one sufficiently precise timeline to identify the sequence surrounding a controlled memory-demand change?

## Preconditions

ENV-001 established usable hosted-runner telemetry.

ENV-002 established an isolated cgroup memory-control surface.

## Controlled workload

The initial workload uses one process with explicit semantic phases:

```text
BASELINE
  ↓
HOTSET_ALLOC
  ↓
HOTSET_TOUCH
  ↓
BURST_ALLOC
  ↓
HOTSET_RETOUCH
  ↓
BURST_RELEASE
  ↓
COMPLETE
```

The workload deliberately exposes its own phase transitions.

This is ground truth for the application-side state machine, not a claim about arbitrary applications.

## Application events

Each event records:

- monotonic timestamp;
- phase;
- phase latency where applicable;
- declared live allocation;
- workload parameters.

## OS/cgroup events

At the same event boundary, the workload records:

- `memory.current`;
- `memory.peak`;
- `memory.high`;
- `memory.max`;
- `memory.events`;
- selected `memory.stat` counters;
- `memory.pressure`;
- `memory.swap.current`.

## Initial cgroup budget

- `MemoryHigh = 160 MiB`;
- `MemoryMax = 256 MiB`.

Workload allocations are intentionally bounded below `MemoryMax`.

## Acceptance

OBS-001 PASS requires:

1. the expected phase sequence is present;
2. monotonic timestamps are strictly increasing;
3. every phase has a readable cgroup memory snapshot;
4. the declared cgroup limits are observed;
5. no OOM event occurs.

OBS-001 does **not** require a particular amount of pressure or reclaim.

The first purpose is synchronized observability.

## Exit condition

OBS-001 establishes that the repository can reproduce a shared timeline connecting:

```text
application state transition
        ↕
cgroup / OS memory state
        ↕
measured phase latency
```

Only after this baseline is stable should CHAR-001 deliberately search for a performance-collapse boundary.
