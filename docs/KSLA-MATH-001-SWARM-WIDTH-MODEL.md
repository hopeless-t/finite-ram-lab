# KSLA-MATH-001 — Swarm Width as an Order-Statistics Control Problem\n\nStatus: **ANALYTIC MODEL / NO NEW SOLVER CLAIM**\n\nParent: **KSLA-002**\n\n## Why Monte Carlo is not the first optimizer\n\nMonte Carlo is excellent for estimating unknown distributions, validating a policy, and measuring rare tails.\n\nIt is not, by itself, the cleanest description of why an optimal kitten count should exist.\n\nThe first useful model is an order-statistics control problem.\n\n## One imaginary kitten\n\nLet the current system state be `s` and let `V(s)>=0` be a potential such as squared residual norm.\n\nA random kitten proposes action `A` and produces the next state `T(s,A)`.\n\nDefine useful progress:\n\n`Y = max(0, V(s)-V(T(s,A)))`.\n\n`Y=0` means the validator rejects the kitten or the action gives no useful progress.\n\nLet `F_s(y)=P(Y<=y)`.\n\n## b kittens in one round\n\nIf b independent kittens appear and the validator keeps the best useful action:\n\n`G_b = max(Y_1,...,Y_b)`.\n\nTherefore:\n\n`P(G_b<=y)=F_s(y)^b`.\n\nAnd:\n\n`E[G_b] = integral_0^inf [1-F_s(y)^b] dy`.\n\nThe probability that at least one kitten is useful is:\n\n`1-(1-p_s)^b`, where `p_s=P(Y>0)`.\n\n## Why a knee exists\n\nThe marginal value of kitten b is:\n\n`Delta_b = E[G_b-G_(b-1)]`\n\nwhich can be written as:\n\n`integral_0^inf F_s(y)^(b-1) * (1-F_s(y)) dy`.\n\nAs b increases, this marginal term cannot increase.\n\nSo the expected value of additional kittens has diminishing returns.\n\nIf each proposal has any positive validation / queue / memory / communication cost, an interior optimum becomes natural.\n\nA local efficiency objective is:\n\n`eta_s(b)=E[G_b]/C_s(b)`\n\nwith:\n\n`C_s(b)=c_fixed + b*c_validate + c_apply*P(G_b>0) + c_queue(b) + resource prices`.\n\nThe rule is conceptually simple:\n\n> keep adding kittens while the next kitten's expected marginal progress is worth more than its marginal resource cost.\n\n## Multiple kitten species\n\nFor action families `a=1..K`, let family a have CDF `F_a,s` and count `b_a`.\n\nThen the accepted best improvement has:\n\n`P(G<=y)=product_a F_a,s(y)^b_a`.\n\nHence:\n\n`E[G]=integral_0^inf [1-product_a F_a,s(y)^b_a] dy`.\n\nThis gives a direct mathematical home for drunk kittens, stale kittens, block kittens, tiny-step kittens, and other action families.\n\nThe next extra kitten should be chosen by marginal expected progress per unit cost while stationary assumptions remain valid.\n\nBecause expected maximum has diminishing returns, repeatedly over-investing in one family becomes less attractive.\n\n## State dependence changes the problem\n\nKSLA is not really stationary.\n\nNear the solution:\n\n- useful proposals become rarer;\n- useful step scales change;\n- the same family can move from valuable to useless;\n- stale proposals can become harmful.\n\nTherefore the full problem is a stochastic control problem.\n\nA compressed Bellman form is:\n\n`J(s)=min_bvec C(s,bvec)+E[J(next_state)]`.\n\nIn practice the full state is too large, so use buckets such as:\n\n- log residual norm;\n- local curvature / condition proxy;\n- recent acceptance rate;\n- queue depth;\n- validator utilization;\n- RAM pressure;\n- stale-action fraction.\n\nThen dynamic programming or an approximate MDP can choose the action-family mixture by state bucket.\n\n## Where bandits fit\n\nBandits are useful only after separating this point.\n\nIf the reward distribution of kitten families is unknown or drifting, the controller must learn which family is currently useful.\n\nThen a contextual or cost-aware bandit can allocate proposal budget across families.\n\nBest-arm identification literature explicitly studies the trade between sampling cost and identifying useful arms, so it is a close outer-control relative rather than the numerical solver itself.\n\n## Where Monte Carlo fits\n\nMonte Carlo should do four jobs:\n\n1. estimate `F_a,s(y)` when it cannot be enumerated;\n2. compare complete policies using matched random tapes;\n3. estimate p95/p99/p99.9 cost and convergence tails;\n4. search rare stale/corrupt/false-accept states.\n\nIf harmful tails become too rare for naive Monte Carlo, use importance sampling / rare-event methods.\n\nSo the recommended order is:\n\n`analytic model -> exact enumeration where possible -> Monte Carlo validation -> rare-event acceleration`.\n\n## KSLA-002 empirical resource-price frontier\n\nThe frozen KSLA-002 endpoints allow a simple cost model:\n\n`J(b)=proposal_count + lambda_round * round_count`.\n\n`lambda_round` means how many proposal evaluations one serial round of latency is worth.\n\nThe lower envelope is:\n\n| lambda_round interval | optimal frozen batch |\n|---:|---:|\n| 0 .. 1272/73 (~17.42) | 8 |\n| 1272/73 .. 2208/47 (~46.98) | 16 |\n| 2208/47 .. 400/3 (~133.33) | 32 |\n| 400/3 .. 5696/33 (~172.61) | 64 |\n| >= 5696/33 | 128 |\n\nBatch 1 and batch 4 never lie on this two-resource lower envelope.\n\nThis proves an important systems point for the frozen fixture:\n\n`the optimal kitten count is a function of resource prices, not a universal constant`.\n\nIf proposal evaluation is expensive and latency is cheap, choose a narrow swarm.\n\nIf serial latency is expensive, wider swarms become rational.\n\nRAM, energy, network bytes, or verifier occupancy can be added as more prices or hard constraints.\n\n## A stronger warning: greedy smart search is not globally smart\n\nThe exhaustive KSLA-002 arm chooses the best immediate action from every coordinate/step combination each round.\n\nYet its trajectory needs 124 rounds, while the random BATCH_128 trajectory reaches exact solution in 122 rounds.\n\nThis does not mean random search is generally better.\n\nIt means that immediate residual reduction is not automatically the globally optimal long-horizon control objective.\n\nThat is another reason to use a dynamic model rather than equating 'best local move' with 'best policy'.\n\n## Experimental correction discovered by the model\n\nKSLA-002 froze separate random domains for each batch width.\n\nThat makes the arms reproducible, but it does not make them matched counterfactuals.\n\nBatch 8 and batch 16 did not receive the same first eight proposals.\n\nThe next width experiment must use **common random numbers**:\n\n`proposal(seed, round_id, proposal_index, action_family, parameters)`.\n\nThen width b consumes proposal indices `[0,b)` from the same tape.\n\nThis lets us ask the clean causal question:\n\n> what changed because we admitted eight additional kittens, rather than because the entire random universe changed?\n\nThis repeats an earlier Finite RAM lesson:\n\n`random-stream identity is part of the frozen experimental state`.\n\n## Recommended optimizer hierarchy\n\n1. **Current one-parameter swarm width:** exact enumeration / analytic order statistics.\n2. **Known multi-family mixture:** marginal-gain-per-cost allocation under CPU/RAM/latency budgets.\n3. **Known state-dependent dynamics:** dynamic programming / approximate MDP.\n4. **Unknown or drifting family quality:** contextual / cost-aware bandit.\n5. **Policy validation and tails:** matched-seed Monte Carlo.\n6. **Rare harmful states:** importance sampling / rare-event search.\n7. **Large expensive outer hyperparameter space:** Bayesian optimization around the simulator.\n\nMonte Carlo is therefore essential, but it is not the mathematical optimizer by itself.\n\n##
