# EXP-002 — Semantic PAGEOUT Value Under Natural Pressure

> **Status:** FROZEN / READY TO IMPLEMENT

## Question

Can one bit of application semantic knowledge — which equal-size region is **not needed next** — improve next-use behavior under natural transition-zone pressure using the existing `MADV_PAGEOUT` interface?

## Workload

Every trial creates:

- semantic HOT region: 32 MiB;
- semantic COLD region: 32 MiB;
- burst region: 96 MiB.

Cgroup:

    MemoryHigh = 164 MiB
    MemoryMax  = 320 MiB

The future phase always retouches HOT.

Physical mapping identity assigned to HOT is balanced A/B inside every arm and runner block.

## Arms

### CORRECT_PAGEOUT

Before the burst, PAGEOUT-prepare the first 16 MiB of semantic COLD.

### WRONG_PAGEOUT

Before the burst, PAGEOUT-prepare the first 16 MiB of semantic HOT.

### NO_HINT

No advice.

All arms then execute the same 96 MiB burst and the same HOT retouch.

No explicit `memory.reclaim` is used.

## Frozen design

- 20 independent runner blocks;
- 6 repeats per arm per block;
- 360 total trials.

## Measurements

Before HOT retouch record:

- HOT resident fraction;
- COLD resident fraction;
- cgroup swap;
- reclaim/refault counters.

Performance outcomes:

1. **HOT retouch latency** — mechanism-sensitive primary outcome;
2. **hint-to-HOT-completion interval** — includes PAGEOUT cost, burst cost, and HOT retouch cost.

The second metric prevents a prepayment of work from being silently called a net benefit.

## Primary inference

Primary pre-registered comparison:

    CORRECT_PAGEOUT vs NO_HINT

For each runner block compute:

    mean(log correct HOT-retouch latency)
      - mean(log no-hint HOT-retouch latency)

Evaluate the 20 block contrasts with exact sign-flip inference over all:

    2^20 = 1,048,576

sign assignments.

Report a cluster-bootstrap interval for the geometric mean ratio.

## Red-Team directional contrast

Pre-register:

    WRONG_PAGEOUT vs CORRECT_PAGEOUT

with the same block-level log-latency contrast.

This is a directional validation of the semantic mechanism.

## Interpretation discipline

Three different outcomes are possible:

- **mechanism benefit** — correct semantic preparation lowers future HOT retouch cost;
- **net benefit** — the broader hint-to-HOT interval also improves;
- **cost shifting only** — future HOT cost improves but total interval does not.

Do not merge these conclusions.

## Authority boundary

A positive result would show value for one semantic signal through one existing Linux interface.

It would not automatically justify a persistent userspace coordinator, a new kernel API, or a custom memory policy.
