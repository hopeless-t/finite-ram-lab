# VAL-001 — Cross-Runner Boundary Validation

> **Status:** IMPLEMENTED / FROZEN CONTRACT

## Question

Does the CHAR-001 pressure/no-pressure regime transition survive replacement of the GitHub-hosted runner, and where does the transition lie on a finer 4 MiB grid?

## Design

VAL-001 uses the Monte-Carlo-selected **D2_FINE_BALANCED** design:

```text
levels:
160 164 168 172 176 180 184 188 192 MiB

independent hosted-runner blocks:
6

repeats per level per block:
2

total trials:
108
```

Each block runs every level, which makes the experiment paired within runner while still testing replication across independent runner VMs.

Within each block the execution order is deterministically shuffled with a block-specific seed.

## Controlled workload

The OBS-001 workload is unchanged:

- hot set: 64 MiB;
- burst: 96 MiB;
- MemoryMax: 320 MiB;
- primary outcome: `HOTSET_RETOUCH` latency.

Changing the workload during validation would confound the replication question.

## Analysis

The analysis reports:

- every raw trial;
- per-runner/per-level median latency;
- per-runner breakpoint estimate on log latency;
- level-wise median across runner blocks;
- endpoint ratios;
- pressure counters;
- cluster-bootstrap breakpoint distribution obtained by resampling whole runner blocks.

Runner blocks, not individual trials, are the top-level replication unit.

## Scientific execution versus replication result

The workflow can execute successfully even if the CHAR-001 phenomenon does not replicate.

Execution PASS means the declared experiment was performed correctly.

The replication result is interpreted afterward from the evidence.

This prevents the workflow from treating a scientifically negative result as infrastructure failure.

## Falsifying outcomes

Any of the following would weaken the current boundary claim:

- large disagreement in breakpoint location between runner blocks;
- no clear latency separation on several independent runners;
- disappearance of the pressure/no-pressure split;
- broad transition incompatible with the earlier sharp-looking grid;
- evidence that runner identity dominates MemoryHigh.

## Non-claims

VAL-001 still does not identify the mechanism.

A replicated boundary does not by itself distinguish swap cost, reclaim timing, residency mismatch, fundamental capacity shortage, or application/OS information gap.
