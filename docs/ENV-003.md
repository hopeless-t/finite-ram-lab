# ENV-003 — Selective Anonymous Pageout Capability Probe

> **Status:** FROZEN PROBE CONTRACT

## Bounce objective

Determine whether the hosted runner can selectively evict a declared anonymous application region with `madvise(MADV_PAGEOUT)` while leaving a matched control region largely resident.

This is an instrument/calibration bounce, not a mechanism experiment.

## Pseudo-Council convergence

### Kernel / VM reviewer

A causal test of “which region lost residency?” needs an intervention that changes region identity while keeping the workload structure fixed.

### Experimental reviewer

Do not begin with a full mechanism claim. First verify that the intervention is available and measurable on the GitHub-hosted kernel.

### Falsification reviewer

The probe fails if `MADV_PAGEOUT` is unavailable, does not measurably reduce residency of the selected region, or indiscriminately removes the matched control region.

### Measurement reviewer

Use the already validated anonymous `mmap + mincore(2)` instrumentation. Measure before and after residency, cgroup swap, and call duration.

### Authority reviewer

A successful probe authorizes a later selective-residency intervention experiment. It does not show that Linux made a bad eviction decision.

## Method

Create two equal anonymous private mappings:

- target region: 64 MiB;
- matched control region: 64 MiB.

Touch both completely.

Under a deliberately unpressured cgroup budget:

```text
MemoryHigh = 512 MiB
MemoryMax  = 768 MiB
```

request `MADV_PAGEOUT` on the full target mapping only.

Record:

- target/control residency before;
- target/control residency after;
- `memory.swap.current`;
- selected memory.stat counters;
- madvise call result/duration.

## Probe PASS

PASS requires:

1. `MADV_PAGEOUT` returns success;
2. target residency decreases by at least 25 percentage points;
3. control residency remains at least 95%;
4. no OOM occurs.

The threshold is a capability criterion only.

## Next bounce if PASS

Design a paired causal experiment that pages out equal amounts from either the hot set or a non-hot semantic region and compares subsequent hot-set retouch latency.

## Next bounce if FAIL

Do not force the mechanism. Re-evaluate candidate interventions such as cgroup reclaim or other existing kernel interfaces.
