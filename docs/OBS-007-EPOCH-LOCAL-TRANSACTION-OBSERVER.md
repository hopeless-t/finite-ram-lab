# OBS-007 — Epoch-local transactional trace observer

> Status: PREFLIGHT IMPLEMENTED / NO PHYSICAL RUN  
> Chapter: finite-ram-lab II  
> Goal: convert native trace windows into source-grounded B400 receipts while preserving epoch-local identity.

## 1. New observer requirement

B400 can no longer classify a measured touch from net memory.current.

For every touch, the observer must separate:

- direct page_counter_try_charge(64)
- refill_stock(63)
- drain_stock
- source-grounded LRU release
- PTE growth
- CPU/worker validity
- trace completeness

Chapter II adds a second requirement:

> state identity must be epoch-local.

A release-only event may occur on a ZERO touch where there is no charge event in the same window.

Therefore the target memcg page-counter identity cannot be rediscovered independently on every touch.

It must be learned from the verified direct-Q64 window and carried only inside that epoch.

## 2. Epoch owner identity

When a NORMALIZE window contains exactly:

- one page_counter_try_charge(...,64)
- one refill_stock(...,63)
- a complete PRE/POST marker pair

the page_counter pointer from the charge event becomes:

`owner_counter(epoch)`

Subsequent release attribution uses that exact counter.

At REPRIME:

`owner_counter := NULL`

The old counter has no authority in the new epoch.

A new direct Q64 must establish a new epoch-local owner.

## 3. Positive RELEASE_ONLY classification

A page_counter_uncharge(...,17) is classified as RELEASE_ONLY only when:

1. its counter equals the current epoch owner counter;
2. the same measured window contains an LRU flush with batch size 31;
3. the same measured window contains folios_put with batch size 31;
4. the marker window is complete.

The current task/comm need not be the owner.

This intentionally preserves the OBS-005 result that a different task can trigger release of folios owned by the target cgroup.

An owner-counter uncharge17 without the complete LRU signature is:

`UNKNOWN_EMISSION`

and fails closed.

An uncharge on another counter is not attributed to the target epoch.

## 4. Transaction marker

Frozen marker form:

`FRL_TX trial=<block:id> epoch=<n> phase=<NORMALIZE|CONSUME|TARGET> touch=<n> PRE|POST`

A valid source window requires:

- exactly one PRE
- exactly one POST
- matching trial/epoch/phase/touch
- monotonic trace timestamps
- no nested or orphan marker error

Missing or malformed marker structure makes:

`trace_complete = false`.

## 5. Receipt packet v2

New schema:

`schemas/TRANSACTION-RECEIPT-PACKET-v2.schema.json`

v2 extends the B400 packet with Chapter-II hazard coordinates:

- touch_index_since_verified
- elapsed_ns_since_verified
- expected_residual_before
- expected_residual_after
- owner_counter
- marker_pre_ns
- marker_post_ns
- unknown_emission_count

v1 remains frozen for historical compatibility.

## 6. Hazard clock

The direct-Q64 verification touch is defined as:

- touch_index_since_verified = 0
- elapsed_ns_since_verified = 0

The first post-verification measured transition is age 1.

This removes an off-by-one ambiguity from later epoch-hazard analysis.
