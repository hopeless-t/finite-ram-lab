# HYP-001 — Future-Reuse Alignment Experiment

> **Status:** IMPLEMENTED / NOT YET RUN

## Question

At the same 164 MiB memcg pressure condition, does the next-use cost differ when future reuse is aligned versus misaligned with the immediately preceding access order?

## Matched semantic regions

The 64 MiB hot set is split into:

- region A: 32 MiB;
- region B: 32 MiB.

Both regions receive the same number of pre-burst touches.

Only the final ordering differs, producing one “more recent” and one “less recent” semantic region without changing total work.

The identity of the more-recent physical mapping is balanced between A and B.

## Primary arms

After a 96 MiB burst:

- **ALIGNED** retouches the region that was made more recent;
- **MISALIGNED** retouches the region that was made less recent.

The kernel receives no semantic hint.

## Frozen design

- 20 independent hosted-runner blocks;
- 6 repeats per arm per block at 164 MiB;
- 160 MiB and 168 MiB endpoint controls;
- 280 total trials.

## Primary inference

For each runner block:

1. compute mean log retouch latency in MISALIGNED trials;
2. subtract mean log retouch latency in ALIGNED trials;
3. test the 20 block contrasts with an **exact sign-flip randomization test** (2^20 assignments);
4. report a cluster bootstrap interval for the geometric mean latency ratio.

This preserves runner as the replication unit.

## Secondary observations

Descriptive only:

- swap-ins during retouch;
- anonymous refaults;
- major faults;
- scan/steal;
- swap present after the burst.

## Falsification

The hypothesis is weakened if ALIGNED and MISALIGNED outcomes are indistinguishable at the sensitivity of the frozen design.

A null result is not proof of zero information value because the design study showed limited sensitivity to small effects.

## Authority boundary

No `madvise`, `mlock`, application hint, coordination service, or kernel modification is used.

The experiment tests information alignment in the workload, not a proposed product architecture.
