## Execution

The second ENV-003 run used the existing Python mmap advice method with the Linux pageout advice value.

Across 4 independent hosted-runner blocks and 8 total target trials:

- all calls succeeded;
- content integrity was preserved;
- no OOM event occurred;
- both semantic target types behaved similarly.

## Observed effect

For both hot-set and burst targets:

```text
requested range = 16 MiB
median swap growth = 16 MiB
mincore residency reduction after 100 ms = 0
```

Median target retouch time was about:

- hot set: 5.26 ms;
- burst: 5.44 ms.

The same probe without a successful pageout call had previously retouched the 16 MiB range in about 0.3 ms.

## Interpretation

The operation successfully established swap backing for the requested anonymous range and preserved data.

However, the requested pages still appeared resident to `mincore` after the call.

Linux kernel documentation notes that `mincore` treats pages in the swap cache as resident. Therefore swap accounting and mincore residency are not contradictory here: a page may have an associated swap entry while still having an in-memory folio.

## Pseudo-Council conclusion

```text
PARTIAL
```

It is sufficient to create explicit swap backing and additional refault/PTE work, but it is **not sufficient by itself** to produce the intended low-pressure “physically nonresident target range” condition.

Do not launch the matched semantic-region mechanism experiment yet.
