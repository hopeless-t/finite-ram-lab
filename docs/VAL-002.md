# VAL-002 — mincore Observer-Effect Validation

> **Status:** IMPLEMENTED / FROZEN CONTRACT

## Question

Did the pre-retouch `mincore(2)` observation itself materially change the 164 MiB transition-zone behavior seen in OBS-002?

## Why this is required

OBS-002 found a strong relationship between hot-set residency after `BURST_ALLOC` and retouch latency.

However:

- the bytearray-based VAL-001 transition zone had rare extreme latencies up to seconds;
- the mmap + mincore OBS-002 transition zone did not;
- some `mincore` calls took milliseconds, which is not negligible relative to a fast retouch.

The observation method must therefore be tested as a possible intervention.

## Pseudo-Council

### Measurement reviewer

An observer that changes the phenomenon cannot be treated as a neutral measurement device.

### Kernel reviewer

`mincore` is a residency snapshot. It should not be assumed to preserve state or be behaviorally invisible merely because it does not intentionally fault pages in.

### Statistics reviewer

Use a randomized paired A/B design within each runner.

Runner identity must remain a block because GitHub-hosted VMs vary.

### Falsification reviewer

If FULL and NONE modes differ materially at 164 MiB, OBS-002 remains useful as an instrumented-system result but cannot directly describe the uninstrumented transition zone.

## Design

Eight independent hosted-runner blocks.

Per block:

```text
160 MiB: mincore FULL x1, NONE x1
164 MiB: mincore FULL x4, NONE x4
168 MiB: mincore FULL x1, NONE x1
```

Total:

```text
96 trials
```

The same anonymous mmap allocator is used in both modes.

The only intended difference is whether residency snapshots are taken during the workload.

## Primary analysis

At 164 MiB:

1. log-transform retouch latency;
2. compute the within-runner FULL-minus-NONE difference;
3. combine runner-block differences;
4. run a 100,000-draw within-block label permutation test;
5. cluster-bootstrap whole runner blocks 5,000 times for an effect-ratio interval.

The estimated effect is reported as:

```text
geometric latency ratio = FULL / NONE
```

No “non-inferiority” margin is invented after seeing the data.

## Supporting analysis

Compare FULL versus NONE for:

- burst-allocation latency;
- swap present after burst;
- retouch swap-ins;
- anonymous refaults;
- major faults;
- scan/steal activity.

## Controls

160 and 168 MiB are preserved in both modes.

They test whether the broad pressured/unpressured regimes survive observation-mode changes.

## Scientific outcome

Execution PASS does not imply observer equivalence.

Possible scientific outcomes:

- little detectable difference between FULL and NONE;
- meaningful timing difference but similar reclaim state;
- major state-distribution change;
- runner-dependent observer effect.

Any is valid.

## Decision boundary

Only if the observer effect is acceptably characterized may mincore-based semantic-residency measurements be used to motivate a mechanism-specific intervention.
