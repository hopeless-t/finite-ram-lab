# OBS-002 — Region-Resolved Residency Observation

> **Status:** IMPLEMENTED / FROZEN CONTRACT

## Question

When the 164 MiB transition-zone workload becomes slow, did `BURST_ALLOC` remove residency from the soon-reused hot-set region?

## Motivation

VAL-001 showed that identical aggregate `MemoryHigh = 164 MiB` conditions can lead to very different retouch latency.

Exploratory phase analysis showed that slow runs had much more anonymous swap-out before the retouch and then thousands of swap-ins/refaults during the retouch.

Aggregate cgroup counters cannot identify which semantic application region lost residency.

OBS-002 adds that observation.

## Instrumentation

The workload uses two anonymous private `mmap` regions:

- **hotset** — 64 MiB, repeatedly touched and then reused;
- **burst** — 96 MiB, allocated/touched after the hot set.

Linux `mincore(2)` snapshots record whether each page of each mapping is resident.

The critical observation point is:

```text
BURST_ALLOC completed
        ↓
mincore(hotset)
mincore(burst)
        ↓
HOTSET_RETOUCH begins
```

No residency hint or memory policy is changed.

## Observation design

The Monte-Carlo-selected O2_BALANCED design uses 8 independent runner blocks.

Per block:

```text
160 MiB x 1   pressured control
164 MiB x 4   transition zone
168 MiB x 1   unpressured control
```

Total: 48 trials.

Order is deterministically shuffled independently in every runner block.

## Primary relationship

Predictor:

```text
hotset resident fraction immediately after BURST_ALLOC
```

Outcome:

```text
HOTSET_RETOUCH latency
```

Supporting observations include:

- hot-set missing pages;
- burst-region residency;
- anonymous swap-ins during retouch;
- anonymous workingset refaults during retouch;
- major faults during retouch;
- scan/steal deltas;
- swap present after burst allocation;
- `mincore` call duration.

## Instrumentation validity

Changing from Python `bytearray` storage to anonymous `mmap` may change allocation/reclaim behavior.

Therefore every runner block contains the previously established 160 MiB and 168 MiB controls.

OBS-002 interpretation is weakened if those controls no longer show the qualitative pressure/no-pressure separation.

## Falsification

The region-residency candidate is weakened if:

- slow retouches occur while the hot set remains fully resident;
- hot-set residency loss is unrelated to retouch swap-ins/refaults;
- the instrumented workload fails to reproduce the established controls.

## Observer effect

`mincore` returns a residency snapshot; it does not provide a durable guarantee that pages remain resident after the call.

Every call duration is recorded so instrumentation overhead remains visible.

## Authority boundary

OBS-002 may establish a region-identity relationship.

It does not yet prove that application hints or a coordination plane improve the outcome.

No `madvise`, `mlock`, memory hint, coordinator, or kernel change is used.
