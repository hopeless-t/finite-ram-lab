# ENV-001 — GitHub-Hosted Memory Observability Probe

> **Status:** IMPLEMENTED / INITIAL CONTRACT

## Question

Which memory-pressure, reclaim, fault, cgroup, swap, and platform signals are actually observable on the selected GitHub-hosted Ubuntu runner?

## Why first

The project uses GitHub Actions as its primary experimental substrate.

Before OBS-001 depends on kernel telemetry, the environment itself must be characterized.

## Signals probed

- platform and kernel identity;
- visible CPU count;
- `/proc/meminfo`;
- selected `/proc/vmstat` counters;
- `/proc/pressure/memory`;
- `/proc/swaps`;
- cgroup v2 detection;
- root cgroup memory controls/statistics when readable;
- relevant GitHub runner provenance environment variables.

## Acceptance

ENV-001 PASS means:

1. the probe completes;
2. a valid structured JSON document is produced;
3. every declared signal is represented as either `SUPPORTED`, `UNAVAILABLE`, or `ERROR`;
4. core provenance is present.

ENV-001 does **not** require every Linux memory facility to be available.

An unavailable facility is a result.

## Non-claims

ENV-001 does not measure memory-policy quality, application demand, bare-metal DRAM behavior, physical SSD performance, or general Linux performance.

## Evidence

The GitHub Actions workflow uploads the JSON probe result as a run artifact.

Runner-image or kernel changes are treated as environment changes.
