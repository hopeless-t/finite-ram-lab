# EXP-003 — High-Headroom Semantic PAGEOUT Probe

> **Status:** FROZEN EXECUTABLE DESIGN
> **Scientific evidence:** NONE YET

## Question

At the 160–162 MiB regime where HYP-003 exposed a large past-state-versus-future-demand mismatch, can the already-qualified 16 MiB `MADV_PAGEOUT` action capture any of that headroom when directed by correct future semantics, without unacceptable wrong/stale-action harm?

This is a mechanism probe, not a preferred architecture.

## Why this experiment is authorized now

The scientific sequence is:

```text
CHAR-002
initial fault/touch order affects later residency
        ↓
HYP-003
future HOT demand is independently assignable
and mismatch is expensive
        ↓
VOI-001
decision headroom is material but wrong-action cost matters
        ↓
EXP-003
test one existing low-authority action in that high-headroom regime
```

EXP-002's negative result at 164 MiB remains valid and is not overwritten.

```

```

## Intervention

Region size:

```text
logical HOT/COLD region = 32 MiB
PAGEOUT target          = first 16 MiB of one logical region
burst                   = 96 MiB
```

Use `MADV_PAGEOUT` before burst allocation/touch.

Definitions:

- **CORRECT_PAGEOUT:** PAGEOUT first 16 MiB of semantic COLD;
- **NO_HINT:** no memory advice;
- **WRONG_PAGEOUT:** PAGEOUT first 16 MiB of semantic HOT.

The 16 MiB target size is frozen from prior capability/intervention work and must not be tuned after EXP-003 data are visible.

## Workload order

For each trial:

1. allocate one 64 MiB shared mapping;
2. touch lower/upper halves in the frozen initial-fault order;
3. establish content-integrity baseline;
4. use future semantic identity only to choose the intervention arm target;
5. execute PAGEOUT or NO_HINT;
6. allocate/touch the 96 MiB burst;
7. measure lower/upper residency before future HOT reuse;
8. retouch all 32 MiB of semantic HOT;
9. capture post-retouch counters and content integrity.

The treatment therefore deliberately gives the intervention access to future semantic identity before the burst.

That is the information channel being tested.

## Primary benefit stratum

Naturally misaligned trials:

```text
future HOT == first-faulted region
```

This is the stratum where HYP-003 exposed decision headroom.

Aligned trials remain mandatory controls:

```text
future HOT == second-faulted region
```

They test unnecessary-action cost and damage to an already-favored state.

## Primary endpoint

In the naturally misaligned stratum:

```text
runner-block mean log HOT-retouch latency:
CORRECT_PAGEOUT - NO_HINT
```

Alternative:

```text
CORRECT_PAGEOUT < NO_HINT
```

Inference:

- exact one-sided sign-flip across 16 runner blocks;
- all (2^{16}=65,536) assignments;
- 20,000-resample runner-cluster bootstrap;
- report geometric mean ratio CORRECT / NO_HINT with 95% interval.

A ratio below 1 favors CORRECT_PAGEOUT.

## Mandatory net-cost endpoint

Same naturally misaligned stratum:

```text
runner-block mean log total work interval:
CORRECT_PAGEOUT - NO_HINT
```

Use the same exact one-sided sign-flip and cluster bootstrap.

A HOT-retouch improvement may be called **mechanism-sensitive benefit** only.

It may be called **net benefit** only if the total-work endpoint also favors CORRECT_PAGEOUT.

## Mandatory Red-Team endpoints

In the naturally misaligned stratum, pre-register:

### WRONG vs NO_HINT

```text
HOT-retouch log latency:
WRONG_PAGEOUT - NO_HINT
```

Alternative: greater than 0.

### WRONG vs CORRECT

```text
HOT-retouch log latency:
WRONG_PAGEOUT - CORRECT_PAGEOUT
```

Alternative: greater than 0.

Repeat both comparisons for total work interval.

Use exact one-sided sign-flip plus runner-cluster bootstrap.

## Result classification

### Mechanism-sensitive benefit

Allowed only if misaligned CORRECT HOT-retouch primary favors CORRECT under frozen inference.

### Net benefit

Allowed only if:

- mechanism-sensitive benefit is supported;
- misaligned total-work endpoint also favors CORRECT.

### Cost shifting only

HOT-retouch improves but total work does not.

### No benefit

Primary HOT-retouch endpoint does not support CORRECT.

### Unsafe / asymmetric harm

WRONG/stale action harm is large relative to correct-action benefit or aligned controls show material unnecessary-action damage.

Multiple labels may coexist where logically compatible, e.g. mechanism-sensitive benefit + unsafe asymmetric harm.

## Stop rule

If EXP-003 does not establish net benefit, do not tune PAGEOUT range/pressure after seeing the data.

Further PAGEOUT intervention work requires new independent evidence or a newly justified question.

## Authority boundary

A positive EXP-003 result would support only this existing PAGEOUT mechanism under this bounded hosted memcg workload.

It would not authorize:

- deployment;
- a userspace coordinator;
- a new application hint API;
- a kernel change;
- a claim that Linux reclaim is generally defective.
